# 0707 多路召回效果测试

> **测试日期**：2026-07-07  
> **评测集**：150 题（factual 100 / comparative 26 / summary 23 / trap 1）  
> **对比基准**：[eval-results.md](eval-results.md)（2026-05-28，P2 索引）  
> **目标**：验证多路召回（hybrid 向量+BM25、对比题 RRF）是否对检索与答案质量有提升

## 2. 多路召回启用状态确认

代码审查结论：**生产路径默认已启用多路召回**，无需额外开关。

| 配置项 | 当前默认值 | 定义位置 |
|--------|-----------|----------|
| `recall_route` | **`hybrid`** | `RAGPipelineConfig`、`RAGRequest`、CLI `--recall-route` |
| `hybrid_vector_weight` | **0.35** | `retrieval.DEFAULT_HYBRID_VECTOR_WEIGHT` |
| `hybrid_pool_size` | **200** | `retrieval.DEFAULT_HYBRID_POOL_SIZE` |
| 对比题 RRF | **自动触发** | `retrieval.retrieve()` 当 `route=hybrid` + `query_type=comparative` + ≥2 实体 |
| `RAG_COMPARATIVE_ENTITY_RERANK` | **1（开）** | `pipeline/comparative_rerank.py`（Rerank 层，不影响 Recall） |
| `RRF_K` | **60** | `retrieval.RRF_K` |

多路召回两层含义：

1. **Hybrid 双路融合**：向量（Milvus）+ BM25 min-max 归一化加权合并
2. **对比题多路 RRF**：每主体独立 hybrid 召回 → `rrf_fuse()` 融合（`entity_sub_queries` 由 `query_rewrite` 生成）

禁用方式：显式传 `recall_route=vector` 或 `bm25`；无全局环境变量一键关闭。

**dry-run 校验**：150/150 `gold_chunk_id` 全部存在于 `chunks.jsonl`。

| B 纯 BM25 | 78.7% | 84.7% | **92.0%** | 0.750 | 138/150 |
| **C 混合** | **87.3%** | **91.3%** | **92.0%** | **0.843** | **138/150** |

**与历史 P2（eval-results.md）对比**

### 4.3 Pipeline recall 模式（生产对齐）

| 路线 | Recall@3 | Recall@5 | Recall@10 | MRR | 命中 @10 |
|------|----------|----------|-----------|-----|----------|
| A 纯向量 | 80.0% | 83.3% | 86.0% | 0.748 | 129/150 |
| B 纯 BM25 | 78.7% | 84.7% | 92.0% | 0.750 | 138/150 |
| **C 混合(Pipeline)** | 60.7% | 68.7% | **76.7%** | 0.568 | 115/150 |

**重要发现**：Pipeline recall 模式下 hybrid 显著低于 Legacy hybrid（Recall@10：76.7% vs 92.0%，-15.3pp）。

按 query_type（Pipeline hybrid）：

| query_type | Recall@10 | Legacy hybrid Recall@10 | Δ |
|------------|-----------|------------------------|---|
| factual | 82.0% | 95.0% | -13.0pp |
| comparative | 61.5% | 80.8% | -19.3pp |
| summary | 69.6% | 91.3% | -21.7pp |

逐题对比（Legacy hit → Pipeline miss）：**27 题**；反向仅 **4 题**。  
说明 `query_rewrite` 分主体独立 embed + Pipeline 召回路径在 **gold_chunk_id 命中率指标**上与裸 retriever 存在显著偏差，不宜直接用 Pipeline recall 阶段的 Recall@K 衡量多路召回收益。

### 4.4 多路召回相对单路的增益（Legacy，Recall@10）

| 对比 | 混合挽回 | 混合损失 | 净效果 |
|------|---------|---------|--------|
| hybrid vs vector | **11 题** | 2 题 | **+9 题** |
| hybrid vs bm25 | 6 题 | 6 题 | 持平（Recall@10 同为 92%） |

**hybrid 相对 vector 挽回的 11 题**：q21, q34, q38, q63, q80, q116, q122, q126, q132, q135, q140  
**hybrid 相对 vector 损失的 2 题**：q103, q119  
**hybrid 相对 bm25 损失的 6 题**：q30, q69, q77, q89, q119, q139

核心收益在 **浅层排序**：相对 vector，Recall@3 提升 **+7.3pp**（80.0%→87.3%），MRR 提升 **+0.095**；相对 BM25，MRR 提升 **+0.093**（0.750→0.843），Recall@10 持平。

## 6. 结论

### 6.1 多路召回是否启用？

**是。** 代码默认 `recall_route=hybrid`，对比题在 hybrid 路线下自动走多主体 RRF；`RAG_COMPARATIVE_ENTITY_RERANK=1` 控制分主体 Rerank（默认开启）。

### 6.2 多路召回是否对检索有提升？

需先区分「多路召回」的两层含义，再分题型回答：

| 机制 | 作用范围 | 本次验证 |
|------|----------|----------|
| **Hybrid 双路融合**（向量 + BM25 加权） | 全部 150 题 | 有效：Recall@10 与 BM25 持平，MRR 显著更高 |
| **对比题多路 RRF**（分主体 hybrid → RRF 融合） | 仅 comparative 26 题 | **gold_chunk 命中率未提升**（见 §6.6） |

**全量 150 题（Legacy，主要来自 Hybrid 融合，而非对比题 RRF）：**

| 维度 | 结论 |
|------|------|
| Recall@10 vs 纯向量 | **+6.0pp**（86%→92%），净多命中 9 题 |
| Recall@10 vs 纯 BM25 | 持平（92%），但 **MRR +0.093**（浅层排序显著更优） |
| Recall@3/5 vs 单路 | 混合在浅层召回全面领先，有利于 Rerank 前段 |
| 相对历史 P2 | 指标稳定，MRR 微升（0.836→0.843），无回归 |

其中 factual 相对 vector 多挽回 **5 题**，summary 多挽回 **2 题**；comparative 净挽回 **3 题**（+4 / −1）。**整体检索增益的主体是 factual/summary 上的 Hybrid 融合，不能归因于对比题 RRF。**

### 6.3 Pipeline 分主体优化对 Recall 指标的影响

Pipeline recall 模式（含 `query_rewrite` 分主体 embed）在 gold_chunk_id 命中率上 **显著低于** Legacy hybrid（76.7% vs 92.0%）。  
该路径的优化目标（见 [comparative-retrieval-fix.md](comparative-retrieval-fix.md)）是 **多公司证据覆盖** 与 `comparative_insufficient` 消除，而非 gold_chunk 命中率；应用 Pipeline recall 指标评估多路召回会得出偏悲观结论。

### 6.4 Rerank + 生成层

- 检索：Rerank 后 Recall@5 **90.7%**，与历史一致；略牺牲 Top5 召回（-2.7pp）换取排序质量。  
- 答案：Rerank 策略在 LLM 生成下答案准确率 **94.7%**，拒答率更低（4.7% vs 10.7%），生成质量优于直接 Top5。

### 6.5 总体判断

| 问题 | 答案 |
|------|------|
| Hybrid 融合是否应作为默认路线？ | **是**，全量检索优于纯向量，MRR 显著优于 BM25 |
| 对比题 RRF 是否提升了 gold_chunk 召回？ | **否**，与 P2 持平（80.8%），且低于纯 BM25（92.3%） |
| 是否存在检索回归？ | **否**（Legacy 路径与 P2 基准一致） |
| Pipeline 对比题优化是否伤害 Recall？ | 在 gold_chunk 指标上 **是**（-15.3pp），需用专项指标（双公司覆盖）评估 |

### 6.6 对比题专项：多路 RRF 是否达到预期？

> **核心问题**：多路 RRF 理论上只针对对比题；若对比题 gold_chunk 准确率不变，则「多路召回提升整体性能」的结论可能主要来自 Hybrid 融合，而非对比题优化本身。

#### 6.6.1 检索层（26 题 comparative，Legacy）

| 路线 | Recall@10 | MRR | 命中数 |
|------|-----------|-----|--------|
| 纯向量 | 69.2% | 0.647 | 18/26 |
| 纯 BM25 | **92.3%** | 0.679 | **24/26** |
| 混合（含 RRF） | 80.8% | **0.744** | 21/26 |
| 历史 P2 混合 | 80.8% | 0.712 | 21/26 |

**结论（检索 / gold_chunk 命中率）：**

1. **相对历史 P2：对比题 Recall@10 完全不变（80.8%）**，未命中题 ID 集合不变 → 对比题 RRF **未带来可观测的 gold_chunk 召回提升**。
2. **相对纯 BM25：混合反而更差**（92.3% → 80.8%，净损失 3 题：q69、q119、q139）。RRF 将多主体 chunk 合并进 Top-10，可能挤占标注 gold_chunk 的位置。
3. **相对纯向量：有净收益**（+4 题挽回，−1 题损失，69.2% → 80.8%），但这部分收益来自 Hybrid 融合 + RRF 的叠加，且仍不及纯 BM25。
4. MRR 从 0.712（历史）升至 0.744（本次），仅表示「命中时排序更靠前」，**不改变命中题数**。

逐题三路命中（1=命中，0=未命中）：

| ID | hybrid | vector | bm25 | 说明 |
|----|--------|--------|------|------|
| q63, q122, q132, q140 | 1 | 0 | 1 | hybrid 相对 vector 挽回，bm25 本已命中 |
| q119 | 0 | 1 | 1 | hybrid 独有损失 |
| q69, q139 | 0 | 0 | 1 | hybrid 损失，bm25 可命中 |
| q62, q66 | 0 | 0 | 0 | 三路均未命中 |

#### 6.6.2 答案层（26 题 comparative，Rerank 评测）

| 策略 | 答案事实准确率 | 检索 Top5 命中率 |
|------|----------------|-----------------|
| 混合直接 Top5 | 53.8%（14/26） | 88.5% |
| 混合 Top30 → Rerank → Top5 | **80.8%**（21/26） | 84.6% |

对比题答案准确率的提升主要来自 **Rerank + LLM 生成**，而非多路 RRF 本身。Rerank 策略在对比题上比直接 Top5 **+27.0pp**，这与全量上的 Rerank 增益模式一致。

#### 6.6.3 对比题 RRF 的设计目标 vs 评测指标

[comparative-retrieval-fix.md](comparative-retrieval-fix.md) 的优化目标是 **Top-5 覆盖 ≥2 家公司**（消除 `comparative_insufficient`），而非 gold_chunk_id 命中：

| 指标（2026-06-10 Pipeline 专项） | 数值 |
|----------------------------------|------|
| Top-5 含 ≥2 家公司 | 23/26（88.5%） |
| `comparative_insufficient` | 3/26（11.5%） |

本次 Legacy 检索评测 **不衡量多公司覆盖**，因此无法直接验证 RRF 在该目标上是否生效；Pipeline recall 模式虽对齐生产路径，但 gold_chunk Recall@10 降至 **61.5%**，说明 **分主体 embed + RRF 与 gold_chunk 标注存在目标冲突**。

#### 6.6.4 直接回答

| 问题 | 回答 |
|------|------|
| 多路 RRF 是否提高了对比题 gold_chunk 准确度？ | **没有。** Recall@10 与 P2 持平（80.8%），命中题数 21/26 不变。 |
| 若对比题表现不变，多路召回是否达到预期？ | **就 gold_chunk 召回而言，未达到预期。** 对比题 RRF 的设计初衷是双主体证据覆盖，当前评测体系未覆盖该目标；在现有指标下看不到收益。 |
| 其他题型的提升来自什么？ | **主要来自 Hybrid 双路融合**（向量 + BM25 加权 + 动态权重），与对比题 RRF 无关。factual 净 +5 题、summary 净 +2 题均由此贡献。 |
| 是否应保留对比题 RRF？ | 保留理由：**MRR 提升**（0.712→0.744）、相对 vector 有净收益、Pipeline 专项评测显示多公司覆盖 88.5%。但不应将其与全量 Recall@10 的提升混为一谈；对比题检索上 **纯 BM25 仍是最强单路**（92.3%）。 |

**修正后的整体表述**：「多路召回」若指 **Hybrid 融合**，对全量检索有效；若指 **对比题 RRF**，在本次 gold_chunk 评测下 **未证明有效**，对其他题型的正面影响应归因于 Hybrid 融合而非 RRF。
