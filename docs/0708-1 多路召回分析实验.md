# 0708-1 多路召回分析实验

> **测试日期**：2026-07-08  
> **目标**：基于 100 题 comparative 专项测试集，定位哪一层技术在拖累对比题 `gold_chunk` 召回率，并验证更偏 BM25 的混合权重是否能改善结果。

---

## 1. 研究问题

0707 的结论已经表明：

- 全量 `hybrid` 路线对 150 题整体有效
- 但 comparative 的 `gold_chunk Recall@10` 没有提升

本次实验专门回答 3 个问题：

1. comparative 检索链路中，**哪一层**在拉低 `gold_chunk Recall/MRR`？
2. comparative 的多路召回设计，是否只是改善“双公司覆盖”，却伤害了 `gold_chunk` 召回？
3. 如果 comparative 更依赖 BM25，那么**调低向量权重**是否能修复召回？

---

## 3. 实验设计

### 3.1 主指标

- Recall@3
- Recall@5
- Recall@10
- MRR
- hit_rate

### 3.2 辅助指标

- `multi_company_top5_rate`
- `comparative_insufficient_rate`
- `avg_distinct_companies_top5`

### 3.3 消融矩阵

脚本：

- `src/eval_comparative_ablation.py`

实验组：


| Variant               | 含义                              |
| --------------------- | ------------------------------- |
| `vector`              | 纯向量                             |
| `bm25`                | 纯 BM25                          |
| `hybrid_plain`        | 原问题直接 hybrid，不拆子查询，不做 RRF       |
| `hybrid_rrf_fallback` | 旧式 RRF：按实体回退构造子查询，但共享原 query 向量 |
| `hybrid_subq_shared`  | 清洗子查询，但仍共享原 query 向量            |
| `hybrid_subq_indep`   | 清洗子查询 + 独立 embedding + RRF      |


这 6 组刚好对应 comparative 链路的关键层：

- 是否拆 comparative 子查询
- 子查询是否独立 embedding
- 是否启用 RRF

### 3.4 权重实验

脚本：

- `scripts/eval_comparative_weight_sweep.py`

扫描权重：

- `0.20 / 0.30 / 0.35 / 0.40 / 0.45 / 0.50 / 0.60`

扫描对象：

- `hybrid_plain`
- `hybrid_rrf_fallback`
- `hybrid_subq_indep`

## 4. 消融结果

结果文件：

- `data/eval/comparative_100/comparative_ablation_summary.csv`
- `data/eval/comparative_100/comparative_ablation_by_tag.csv`

### 4.1 总体结果


| Variant               | Recall@10 | MRR        | Top-5 双公司覆盖率 | `comparative_insufficient` |
| --------------------- | --------- | ---------- | ------------ | -------------------------- |
| `bm25`                | **90.0%** | 0.5855     | **67.0%**    | **33.0%**                  |
| `hybrid_plain`        | **87.0%** | **0.6975** | 47.0%        | 53.0%                      |
| `hybrid_rrf_fallback` | 77.0%     | 0.6696     | 33.0%        | 67.0%                      |
| `hybrid_subq_shared`  | 76.0%     | 0.6760     | 36.0%        | 64.0%                      |
| `hybrid_subq_indep`   | 73.0%     | 0.6329     | 62.0%        | 38.0%                      |
| `vector`              | 70.0%     | 0.6467     | 22.0%        | 78.0%                      |


### 4.2 第一结论：真正最伤召回的是 comparative 子查询 + RRF 链路

以 `hybrid_plain` 为基线：


| 对比                                     | Recall@10 变化 |
| -------------------------------------- | ------------ |
| `hybrid_plain` → `hybrid_rrf_fallback` | **-10pp**    |
| `hybrid_plain` → `hybrid_subq_shared`  | **-11pp**    |
| `hybrid_plain` → `hybrid_subq_indep`   | **-14pp**    |


这说明：

1. **不是 hybrid 本身有问题**
2. 问题主要出在 comparative 专项增强链路：
  - 子查询拆分
  - RRF 融合
  - 独立 embedding

其中伤害最大的是：

- **清洗子查询 + 独立 embedding + RRF**

也就是当前最“完整”的 comparative 检索增强方案。

### 4.3 第二结论：RRF/独立子查询确实提升覆盖，但会牺牲 `gold_chunk` 召回

`hybrid_subq_indep` 与 `hybrid_plain` 对比：


| 指标                         | `hybrid_plain` | `hybrid_subq_indep` |
| -------------------------- | -------------- | ------------------- |
| Recall@10                  | **87.0%**      | 73.0%               |
| MRR                        | **0.6975**     | 0.6329              |
| Top-5 双公司覆盖率               | 47.0%          | **62.0%**           |
| `comparative_insufficient` | 53.0%          | **38.0%**           |


这说明当前 comparative 方案存在明确 trade-off：

- **覆盖更好**
- **召回更差**

也就是说，它更擅长“把两家公司都放进前 5”，但不擅长“把标注 gold chunk 留在前 10”。

### 4.4 第三结论：BM25 是 comparative 最强检索底座

从 `Recall@10` 看：


| 路线                    | Recall@10 |
| --------------------- | --------- |
| `bm25`                | **90.0%** |
| `hybrid_plain`        | 87.0%     |
| `hybrid_rrf_fallback` | 77.0%     |
| `hybrid_subq_indep`   | 73.0%     |
| `vector`              | 70.0%     |


这意味着：

- comparative 下 **BM25 单路最强**
- 当前 hybrid 的主要收益在排序（MRR），而不是命中率超越 BM25
- 一旦叠加 comparative 子查询/RRF，`gold_chunk Recall` 明显被拉低

### 4.5 第四结论：老 26 题与新 100 题趋势一致

`legacy_existing` 26 题上：


| Variant               | Recall@10  |
| --------------------- | ---------- |
| `bm25`                | **92.31%** |
| `hybrid_plain`        | **92.31%** |
| `hybrid_rrf_fallback` | 76.92%     |
| `vector`              | 69.23%     |


这与 0707 的结论一致：

- BM25 很强
- comparative RRF 没有提高 `gold_chunk Recall`
- 扩展到 100 题后，这个结论不是偶然，而是被放大验证了

## 5. 权重实验结果

结果文件：

- `data/eval/comparative_100/comparative_weight_sweep.csv`

### 5.1 `hybrid_plain`


| 向量权重 | Recall@10 | MRR    |
| ---- | --------- | ------ |
| 0.20 | 87.0%     | 0.6975 |
| 0.30 | 87.0%     | 0.6975 |
| 0.35 | 87.0%     | 0.6975 |
| 0.40 | 87.0%     | 0.6975 |
| 0.45 | 87.0%     | 0.6975 |
| 0.50 | 87.0%     | 0.6975 |
| 0.60 | 87.0%     | 0.6975 |


结论：

- 对 `hybrid_plain` 来说，**调权重几乎没有影响**
- 说明当前 `hybrid_plain` 的 comparative 表现，不是由 `0.35` 这个权重点选错导致的

### 5.2 `hybrid_rrf_fallback`


| 向量权重 | Recall@10 | MRR        |
| ---- | --------- | ---------- |
| 0.20 | 77.0%     | 0.6604     |
| 0.30 | **77.0%** | **0.6696** |
| 0.35 | **77.0%** | **0.6696** |
| 0.40 | **77.0%** | **0.6696** |
| 0.45 | 76.0%     | 0.6596     |
| 0.50 | 76.0%     | 0.6579     |
| 0.60 | 75.0%     | 0.6521     |


结论：

- 更偏 BM25（0.30 到 0.40）略优于更偏向量
- 但提升非常有限，无法把 RRF fallback 拉回 `hybrid_plain` 水平

### 5.3 `hybrid_subq_indep`


| 向量权重 | Recall@10 | MRR        |
| ---- | --------- | ---------- |
| 0.20 | 72.0%     | 0.6254     |
| 0.30 | 73.0%     | 0.6346     |
| 0.35 | 73.0%     | 0.6346     |
| 0.40 | 75.0%     | 0.6546     |
| 0.45 | 77.0%     | 0.6796     |
| 0.50 | 78.0%     | 0.6758     |
| 0.60 | **80.0%** | **0.6954** |


结论：

- 对“清洗子查询 + 独立 embedding + RRF”来说，**更偏向量反而更好**
- 这和“comparative 更吃 BM25”的直觉不一致
- 说明问题不只是权重，而是：
  - 子查询后的语义表征本身变了
  - RRF 的组合方式改变了结果排序

### 5.4 权重实验总判断


| 结论                                        | 判断                                                               |
| ----------------------------------------- | ---------------------------------------------------------------- |
| 靠调整 `hybrid_plain` 的权重能否显著提高召回？           | **不能**                                                           |
| 靠调整 `hybrid_rrf_fallback` 的权重能否修复 RRF 伤害？ | **不能**                                                           |
| 靠调整 `hybrid_subq_indep` 的权重能否挽回一部分损失？     | **能，但最多恢复到 80% Recall@10，仍明显低于 `hybrid_plain` 87% 与 `bm25` 90%** |


因此：**权重不是主矛盾，comparative 子查询 + RRF 才是主矛盾。**

## 6. 分标签观察

从 `comparative_ablation_by_tag.csv` 可见：

- `structure_compare`、`logic_compare` 这类题在 `bm25` 和 `hybrid_plain` 下整体更稳
- `same_company_multi_report`、`mixed_financial` 在 `hybrid_plain` 下表现较好
- `risk_compare`、`rating_compare` 本身就是难题，所有路线都弱

两个典型现象：

1. **数值类 comparative** 并没有因为 RRF 更强，反而 `hybrid_plain` 更稳定
2. **逻辑/结构类 comparative**，RRF/独立子查询能提高双公司覆盖，但仍未转化成更高 `gold_chunk Recall`

---

## 7. 结论

### 7.1 哪一层在帮倒忙？

**主因不是 hybrid，而是 comparative 专项增强链路本身。**

按伤害程度看：

1. **清洗子查询 + 独立 embedding + RRF**：伤害最大
2. **旧式 RRF fallback**：也明显伤害召回
3. **仅做 hybrid_plain**：反而是最稳的 comparative 检索方案

### 7.2 对比题多路召回有没有达到提高召回率的目标？

**没有。**

在这 100 题 comparative 测试集上：

- `hybrid_plain` Recall@10 = **87.0%**
- `hybrid_rrf_fallback` Recall@10 = **77.0%**
- `hybrid_subq_indep` Recall@10 = **73.0%**

所以如果目标是 **提高 comparative 的 `gold_chunk Recall`**，当前多路召回方案没有达标，甚至是负贡献。

### 7.3 为什么它看起来“有用”？

因为它确实改善了另一个目标：

- Top-5 双公司覆盖率
- `comparative_insufficient`

也就是说，它是在优化：

- “答案看起来更像比较题”

而不是优化：

- “把标注 gold chunk 找回来”

### 7.4 BM25 倾斜是否能救回来？

**不能从根本上解决。**

- `hybrid_plain` 对权重不敏感
- `hybrid_rrf_fallback` 轻微偏 BM25 仅有小幅收益
- `hybrid_subq_indep` 反而更偏向量更好

说明问题不是简单的权重选错，而是 retrieval 设计本身不适合当前 comparative 召回目标。

---

## 8. 推荐策略

如果目标优先级是 **comparative 的 `gold_chunk Recall/MRR`**，建议：

1. comparative 检索默认先回退到 `**hybrid_plain**`，不要默认走 RRF
2. 如果只看纯召回，甚至可以把 `**bm25**` 作为 comparative 的强 baseline
3. 将 comparative 的“多公司覆盖”优化与“gold_chunk 召回”优化拆成两套策略，不要混在一个 retrieval 方案里

更具体地说：

- **检索优先**：`bm25` 或 `hybrid_plain`
- **覆盖优先**：`hybrid_subq_indep` + comparative rerank
- **最终推荐**：先把 comparative 的 retrieval baseline 改成 `hybrid_plain`，再单独在 rerank / evidence 层补 coverage
